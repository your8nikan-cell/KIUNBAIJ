# Dubai House — development notes

- Run `docker compose -f docker-compose.base44.yml up -d --build`. The one-shot dependencies service runs `npm ci` into a shared volume before the API and Vite start; do not run simultaneous installers against that volume.
- The browser entry is port 3000. Vite proxies `/api` to the private `api:8000` service for same-origin requests. Both app services mount the checkout and watch live source. Preserve `__VITE_ADDITIONAL_SERVER_ALLOWED_HOSTS` for preview host access.
- Node 22.13+ is necessary for `node:sqlite`. Inquiries and subscribers are stored in `/data/inquiries.sqlite` in the `application_data` volume. Never remove that volume during dependency refreshes. There is intentionally no public inquiry-read endpoint.
- Frontend inventory is currently illustrative data in `src/data.js`; favorites persist in localStorage per browser. Contact and newsletter submissions really persist, but do not send mail or contact WhatsApp. No external service credentials are required to boot.
- Photography and Latin webfonts are self-hosted under `public/` because third-party asset delivery failed in the preview browser. `image(id, width)` maps to downloaded 480/960/1800-width images; new photo IDs need matching local files.
- Typography/palette and asymmetric homepage grids follow the supplied Dubai House reference. Keep square architectural image cards, compact navigation, cream/navy rhythm, and serif headlines. Respect reduced motion; reveal effects must not hide unscrolled content.
- Verify with `docker compose -f docker-compose.base44.yml exec -T web npm run build`, `docker compose -f docker-compose.base44.yml exec -T api npm test`, and `curl -f http://localhost:3000/api/status`. API tests use a separate temporary database and process on port 8011, never the preview database.
- Browser verification passed hero query forwarding, filters/sort, load-more (9 → 15), favorites/localStorage, gallery arrows, viewing modal + inquiry POST, location switching, testimonials, and newsletter submissions. Database reads also confirmed both submitted records persisted, then removed only those test records. Desktop full-page appearance was checked after local asset loading.
- Favorites context must stay in `src/state/Favorites.jsx`, never in `main.jsx`: importing the app entry from components caused a context identity mismatch during HMR. The fix passes the build, but the preview-tool call cap prevented a mobile/post-fix browser recheck in this session. Mobile menu, journal filters, chart tabs, and contact-channel presets remain automatically unverified; check those before claiming complete end-to-end coverage.
- Production is not configured or deployed. See README for business-data, image-rights, legal, email delivery, privacy/retention, and hosting requirements. Do not describe illustrative inventory, client quotes, charts, or unverified business credentials as real.
